## 三、zero 对照：实验室的核查是对的，我认

### 3.1 事实

`r7_7b_seed2_zero` 的四个 PPL 与既有 mean 基线**完全相同**（7.979187488555908 对 7.9792，是同一个数）。实验室做了五项独立核查：

1. checkpoint md5 **逐位相同**（`45c1b5df88ac…`）；
2. 635 条 epoch 训练轨迹**逐行相同**（含 NaN 计数 5）；
3. 合成实验定位分歧条件：子集正负混合时 `max|mean−zero| = 0`，全为正时才差 0.268；
4. 接线核查：`shield_mode` 确实落到模块属性，参数没丢；
5. 同机同参 68M 对照：mean = zero = 157.7880。

**结论：数学等价，不是参数丢失。** 这个核查做得比我要求的多，五项都是对的。

### 3.2 为什么会等价（这个解释是关键）

两个分支只改 `mask_low` 之外的通道取值，而输出还要再乘 `mask_low`。所以结果只取决于 `act_quantizer` 的 min/max：

- `mean_low` 落在 `[xmin, xmax]` 内 —— 不改变量程；
- `0` 也落在 `[xmin, xmax]` 内（当子集混合符号）—— 同样不改变量程。

于是输出逐位相同。**只有当子集全正或全负时，`0` 才会把区间拉到 0，两者才分歧。**

真实激活的低显著子集恒为混合符号，所以这个分歧在 LLM 上永远不会出现。

### 3.3 严格说，错在哪

我设计这个对照时，把"零填充会污染量程"当成了一个在真实激活上会体现的缺陷。但那个结论只来自**合成数据**（全正场景 5.16 倍膨胀）。我没有先验证"真实激活是否会出现单符号子集"，就直接拿它当了主对照。

这是设计上的疏漏：**我把一个边界条件的性质，当成了普遍性质。**

### 3.4 但它没有证伪核心创新点 —— 只是证伪了它的一个错误表述

这一点必须说清楚，否则容易误判成"第八轮不用跑了"。

| 命题 | 谁证明 | 状态 |
|---|---|---|
| 量程污染存在（$r = 4.21$，浅层 26.08） | hijack_ratio 实测 | ✅ 成立 |
| **屏蔽（隔离）比不屏蔽好** | **A-off 10.4181 vs Full 7.9792 = 23.4 pp** | ✅ **成立，这是核心** |
| 均值锚定比零填充好 | zero 对照 | ❌ **证伪（等价）** |
| 均值锚定在单符号子集下比零填充稳 | 合成实验 | ✅ 成立但真实模型用不上 |

**真正撑起贡献的是第二行，不是第三行。** 而第二行的对照是 A-off，不是 zero。

## 四、创新点重新定位（这是本轮最重要的判断）

### 4.1 原来的说法（现在站不住）

> "我们提出均值锚定屏蔽，它比零填充更好。"

现在必须改成：

> "我们指出现有双分支量化中低显著分支的量程被高显著通道绑架，并提出**量程隔离**：低显著分支的 scale 只由该子集自身决定。"

### 4.2 均值锚定的角色降级（但没消失）

它从"方法"变成"实现手段"，而且是一个**有明确适用边界**的实现手段：

- 在真实激活（混合符号）下，均值锚定与零填充**逐位等价**；
- 在单符号子集（如 ReLU 后的非负激活、或某些中间层）下，零填充会把量程拉到 0，均值锚定不会；
- 与 ±∞ 精确掩码相比，均值锚定不产生 NaN 梯度。

**这个"等价"本身值得写进论文**，理由不是自曝其短，而是它主动回答了一个审稿人大概率会问的问题："为什么不直接把被屏蔽位置置零？"——答案是"确实一样，我们发现并验证了这一点，但零填充在单符号边界会失效，所以选了均值"。

这种写法比硬说"我的填充方式更好"可信得多。

### 4.3 结论

**核心创新点成立，但名字要改：**从"均值锚定"改成"量程隔离（range isolation）"。

这也意味着 68M 的 zero 腿虽然没达到预期目的，却意外提供了一个有用的负结果：**证明了在这个模型族上，填充值的选择不重要，重要的是是否隔离。**

## 六、我自己的两个失误（要改）

### 6.1 压缩包用反斜杠做路径分隔符

`Compress-Archive` 在 Windows 上写出的 zip 条目名是 `SpikeLLM\lab_...ps1` 这种反斜杠形式，`unzip` 和 `Expand-Archive` 都会出错。实验室用 `zipfile` + `name.replace('\\','/')` 才解开。

**以后打包必须用 Python `zipfile` 显式写正斜杠。** 这条我记住了，下次直接改工具。

### 6.2 把 `$ErrorActionPreference` 设成了 `"Stop"`

PS 5.1 下 python 往 stderr 打一句 `urllib3 ... doesn't match` 的 warning，就会被当成致命错误杀掉子进程。第五、六轮的 runner 都是 `"Continue"`，我这次手滑写成了 `"Stop"`，实验室又帮我改回来了。

**这条应该写进模板，不依赖每轮记忆。**

## 八、回答实验室第七节的 6 个问题

1. **zero 是否作为 v1 基线写进论文**：不作为性能对照，改为 implementation detail 里的一句话。若要保留对照形式，需要构造单符号子集（例如按通道取绝对值后再判显著性），否则恒等于 mean。**我暂不打算做这个构造**，因为真实 LLM 激活不会出现该场景，做了也是自证无用。
2. **68M 三个基线取哪个**：以**同机同版**为准。论文正文若引 68M，统一用实验室实测的 157.7880 / 90.8312（因为 7B 也全在实验室跑，口径一致）。开发机的 156.84 只用于开发期对比内部记录。156.09 来源待查，暂不引用。
3. **是否补 seed=5**：不必。配对差 std 0.0464，效应量 55σ，三种子足够。省下的时间给 A-off 种子。
4. **8B 冒烟**：排下一轮，`--nsamples 64` 先跑通，零样本全部关闭。
5. **ACE/发放率口径**：ACE 已交付（`measure_ace_sops.py`，纯 CPU）。发放率建议：校准集 8 样本 × 2048 token，checkpoint 用 `7b_osdsq_v2_with_let` 与 `7b_original`（同 seed2），逐层统计 1-bit 展开后非零比例。我下一轮补 forward hook 脚本。
6. **acc_norm 口径**：`lm_eval/base.py:660` 按选项字符长度归一，是旧版 lm-eval 的标准行为，与原文 Table 3 所用版本一致。跨表引用原文 49.51 **成立**，但正文须注明"旧版 lm-eval，acc_norm 按字符长度归一"。
