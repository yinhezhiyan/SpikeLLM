## 二、复查结论：B 的"矛盾"不存在，是我读参数时漏了一个开关

### 2.1 事实

我回到 `run_p1_p3_experiments.py` 核对每个消融组的完整参数，发现关键差异：

```python
# 渐进式三步（全部带 --ablate_orig_loss）
("abl_step1_linear_only",  [... "--ablate_no_kv_shield", "--ablate_orig_saliency", "--ablate_orig_loss" ...])
("abl_step2_linear_kv",    [... "--ablate_orig_saliency", "--ablate_orig_loss" ...])
("abl_step3_plus_saliency",[... "--ablate_orig_loss" ...])

# 留一消融（不带 --ablate_orig_loss，即启用 D）
("loo_minus_kv_shield", [... "--ablate_no_kv_shield" ...])
("loo_minus_saliency",  [... "--ablate_orig_saliency" ...])
```

`main.py:247` 对 `--ablate_orig_loss` 的定义是：*"use original equal-weight MSE loss without cosine alignment"*。

也就是说，**渐进式那三组全都在用原版等权 MSE 作蒸馏目标，而留一消融两组用的是本文的加权余弦目标（D）**。我之前把这两组并列，得出"B 的符号矛盾"，这个矛盾是我自己制造的——它们本来就不是同一个实验条件。

### 2.2 修正后的正确读法

| 蒸馏目标 | 无 B | 有 B | B 的效应 |
|---|---|---|---|
| 原版等权 MSE | 160.31 | 162.93 | **−2.62** |
| 本文加权余弦（D） | 158.45 | 156.84 | **+1.61** |

两个条件内部各自一致，B 的符号随蒸馏目标翻转。这是一个**交互效应**，不是矛盾，也不是环境问题。

### 2.3 结论是否有环境因素？

我仍然做了排查，没有发现支持"环境导致"的证据：两组实验的 PPL 量级、FP16 参照、校准集都一致，且 68M 同配置种子噪声仅 0.55%，而 B 的效应是 −2.62 / +1.61，远超噪声。**因此这一项不需要重跑，需要的是补齐缺失的对照格子**（见 §四）。

你的"报告环境"要求本身完全正确，只是没法解释这一项——因为原因在实验设计，不在机器。我已把这个要求做成机制（§三）。

## 三、新增：`env_report.py` 环境指纹脚本

路径：`SpikeLLM/env_report.py`。**建议每批次实验跑完即执行一次，随结果回传。**

```powershell
python env_report.py --note "68M_x2_2x2" --out env_68m_x2.txt
```

报告六个区块：

| 区块 | 内容 | 用途 |
|---|---|---|
| [1] CODE STATE | git commit + 是否有未提交改动 | 代码是否变化 |
| [2] CRITICAL FILE HASHES | `spike_linear.py` / `spike_matmul.py` / `spike_omniquant.py` / `transformer.py` / `main.py` 等 8 个文件的 sha256 | **即使 git 不可用也能判断代码是否变化** |
| [3] RUNTIME | python / torch / transformers / CUDA / cudnn / GPU 型号驱动 | 数值栈差异 |
| [4] ENV VARS | `PYTORCH_CUDA_ALLOC_CONF` 等影响数值的变量 | OOM 与确定性 |
| [5] CACHE | 校准与测试缓存的 sha256 + 大小 | **校准数据不一致会直接让 PPL 不可比** |
| [6] RUN CONFIG | 本次命令行参数 | 防止参数记忆错误 |

**已在开发机试跑，并发现一个真实问题**：本机 git 报 `dubious ownership`（仓库属主 SID 与当前用户不一致），导致 `git status` 直接失败。脚本已改为检测 `fatal:` 并降级为 `UNKNOWN` + 提示修复命令，同时依靠 [2] 的文件哈希兜底判断代码变化。**请实验室首次运行时注意 [1] 是否显示 git usable: no，若是，请执行 `git config --global --add safe.directory <repo>`。**

开发机实测值（供实验室对照）：torch 2.12.0.dev20260408+cu128 / transformers 4.38.2 / CUDA 12.8 / cuDNN 92000 / RTX 5060 Ti。**实验室是 3090，torch 与 CUDA 版本大概率不同，这正是需要记录的原因。**

## 四、需要实验室补的实验：68M 2×2（约 20 min）

为把"B 依赖蒸馏目标"从假设变成结论，需要补齐 2×2 的两个空格。当前已有：原版MSE×{无B, 有B}、D×{有B}、D×无B（但含 C）。

补两组（均开 C 的反面，即保持 `--ablate_orig_saliency`，只切换 B）：

```powershell
# 格子1: D 目标 + 无 B（= A + D，C 关闭）
python main.py --epochs 20 --let --aug_loss --seed 2 --addbit 1 --low_p 0.9 `
  --ablate_orig_saliency --ablate_no_kv_shield --output_dir ./log/x2_d_nob

# 格子2: D 目标 + 有 B（= A + B + D，C 关闭）
python main.py --epochs 20 --let --aug_loss --seed 2 --addbit 1 --low_p 0.9 `
  --ablate_orig_saliency --output_dir ./log/x2_d_b
```

判据：若 `x2_d_nob` 的 PPL **小于** `x2_d_b`（即 D 下加 B 也变差），则我的交互假设被证伪，B 的收益来自 C 与 D 的三方交互，需要重新解释；若 `x2_d_nob` **大于** `x2_d_b` 且差值接近 +1.6，则假设成立，可写入正文作为确定性结论。

单组 68M 约 10 min（历史上 elapsed 573–590 s），两组串行约 20 min。**注意开发机内存不足会崩，请在实验室 3090 上跑。**

跑完请附 `env_report.py` 的输出。
