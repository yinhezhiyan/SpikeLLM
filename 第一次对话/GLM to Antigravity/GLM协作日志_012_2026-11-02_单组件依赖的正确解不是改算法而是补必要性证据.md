## 二、我的结论：不建议改算法，但用户的直觉指向了一个真实缺口

**用户对"不稳"的直觉是对的，但对病因的判断错了。** 缺的不是新算法，是**必要性证据**与**普适性证据**。

### 为什么"独占七到九成"在论文层面反而是优势
- CCF-A 审稿最怕的是"四组件各贡献 25%、每个都落在噪声带内"——第四轮 B(1.6%)、C(1.4%) 正是这种形态，只能进附录。
- 现在的结构是：**发现一类系统性失效 → 该失效单独解释 74%–94% 的性能损失 → 给出无超参解析解**。这是清晰因果链，比堆 trick 强。
- 真正会被打的是"incremental / engineering fix"，而这一指控只能靠**必要性证明**反驳，不能靠再加一个组件反驳。加组件反而坐实"没有抓住本质"。

## 三、建议方案：鲁棒性三件套（不动主算法，约 4–6 小时 GPU）

全部在 68M / 1.1B 上完成，**零算法改动、零新开关、零回归风险**。

### 实验 1（最高优先）：`low_p` × 方法 的二维扫描
- 扫 `low_p ∈ {0.80, 0.85, 0.90, 0.95, 0.98}`，每档跑三组：`orig_spikellm` / 完整 v2 / `ablate_no_linear_shield`
- 68M 每组约 10 min → 15 组约 2.5 h
- **预期与论文价值**：量程绑架比 `r = R_all/R_low` 随 `low_p` 增大而单调增大，A 的相对增益应随之单调放大。若成立，A 就从"0.9 附近的补丁"升级为"**随分流强度单调增长的机制**"——这是比任何消融都硬的一句话，直接封死"特调"质疑。若某档 A 失效，反而说明存在适用边界，如实写入 limitation 也远胜于回避。
- 附带产出：`low_p` 与 `r²` 的定量关系曲线，可直接作为理论章节的实证支撑（现有 fig1 只有单点 0.9）。

### 实验 2：同族替代方案对照（回答"必要性"）
在 68M、`low_p=0.9` 固定下横向对比 4 种低比特分支量程处理：
1. 原版：全通道 min-max（含离群值）
2. 0 填充屏蔽（我们 v1 的做法）
3. `±inf` 掩码精确子集 min-max（数学无偏但 AMP 易 NaN）
4. **均值锚定 `μ_low` 填充（= A，最终方案）**
- 约 40 min
- **价值**：证明 A 不是"随便一个 fix"，而是这一族里**唯一同时满足精确子集量程与数值稳定**的解——(3) 数学等价但工程崩，(2) 有零点偏移。这条对照是"principled solution"与"hack"的分界线。

### 实验 3：bit 宽泛化（回答"跨配置成立"）
`W4A4`（已有）+ 补 `W4A3` / `W3A4`（视代码支持度，68M 各 10 min）
- **价值**：证明 A 的收益来自"低比特分支量程被污染"这一机制本身，而非 4/4 这一特定组合。若时间紧可降级为附录。

### 可选（时间盒 2 h，用户若坚持探索）
只允许一个**有理论依据**的推广方向：把 A 的思想移到**权重侧**（weight 是否存在同类跨分支极值污染）。
- 判据：68M 上若增益 < A 在激活侧增益的 1/3，**永久关闭该方向**，不再消耗 7B/8B 算力。
- 明令禁止：`low_p` 自适应搜索、新显著性公式、任何需要重跑 7B 全量的改动。均会重开实验闭环。

## 四、明确不建议"再打磨几轮算法"的理由

1. **时间不可承受**：ICML 2027 截稿约 1 月底，剩 ~3 个月。改算法需重新定稿 → 7B 全量（7.5 h/腿 × 多腿）→ 8B 全套 → 消融重跑，直接吃掉两个月，写作与 8B 全部落空。
2. **现有证据链已闭环且经交叉验证**：3 seeds（wt2 噪声仅 0.55%）、fake/real 双协议、A-off 语义已回读代码确认等价原版路径、lab 归档 md5 与 checkpoint 逐位校验。
3. **风险结构不对称**：改算法是"用确定的时间换不确定的增益"；补证据是"用确定的时间换确定的审稿防御力"。后者期望收益高一个量级。
4. **顶会被拒的典型形态不是"方法太简单"，而是"证据链不全 + 8B 缺失 + 无系统证据"**。

### 7.2 已完成：数值等价性证明（零 GPU 成本，直接可用）
`log/shield_equivalence_proof.json`，2048 个合成 token，64 通道中 57 个低显著：

| 场景 | 方法 | 量程精确 | 量程膨胀(均值/最坏) |
|---|---|---|---|
| 子集跨正负 | 原版全通道 | 否 | 120.3× / 334.8× |
| 子集跨正负 | 0 填充 (v1) | 是 | 1.00 / 1.00 |
| 子集跨正负 | 均值锚定 (A) | 是 | 1.00 / 1.00 |
| 子集全正 | 原版全通道 | 否 | 558.6× / 1256.6× |
| **子集全正** | **0 填充 (v1)** | **否** | **5.16× / 6.00×** |
| 子集全正 | 均值锚定 (A) | 是 | 1.00 / 1.00 |

**这是论文最有力的一张表**：原版量程被污染上百倍（A 的来源）；0 填充只在子集跨零时侥幸正确，全正子集下量程膨胀 5.16 倍（正好对应 v1 比 v2 差 6.93 PPL）；均值锚定两场景均精确，且与 ±inf 精确子集 min-max 数学等价但无 nan 梯度。
⚠️ 写作注意：上表是**合成极端数据**用于演示机制，不能当作真实激活上的量级；正文用实测 r=2.07 / r²=4.30 与 1.76–3.12× MSE 缩减。
