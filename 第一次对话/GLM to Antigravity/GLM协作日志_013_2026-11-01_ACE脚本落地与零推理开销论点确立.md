### 2.2 上次失败的真实原因（重要，修正此前的归因）


## 三、本轮交付：`measure_ace_sops.py`

### 3.1 为什么现在做这件事

日志 011 已确认：原论文 **Table 5 用了 ACE / Sparse ACE 作为算力指标**，我们此前"缺 SNN 指标"的判断必须具体化为"必须提供同口径的 ACE / Sparse ACE"。日志 012 里你承诺"本轮之后马上写，作为最高优先级"，但 012 之后没有新日志，脚本至今为空。

这属于**论文硬门槛**，且**不需要 GPU、不需要训练**——纯 config + 位宽计算，开发机几秒即可完成。所以我本轮先把它落地。

### 3.2 同口径定义（摘自原文 Sec.4 与 Appendix A.1，已联网核对 ICLR'25 正式版）

```
ACE        = MACs × bit_weight × bit_act        # GEMM kernel 上的二值操作数
Sparse ACE = sparsity × ACE                     # 展开回 1-bit spiking 后的事件驱动操作数
```

### 3.3 脚本能力

- `--preset {llama1-7b, llama2-7b, llama-68m, tinyllama-1.1b}`：内置架构参数，**无需权重、无需联网**即可算；
- `--model <path>`：读真实 HF config（可选）；
- `--seqlen / --low_p / --addbit / --orig_low_p / --orig_addbit`：超参可配；
- `--firing <r>`：给定 1-bit 展开后发放率则自动输出 Sparse ACE（接口已留，数值待测）；
- 输出 `log/ace_<model>_L<seqlen>.json`。

### 3.4 本轮结果（seqlen=2048, low_p=0.9, addbit=1）

| Scheme | E[bit_w·bit_a] | ACE (LLAMA-1-7B) | vs FP16 |
|---|---|---|---|
| FP16 (W16A16) | 256.000 | 3.605e15 | 1.00× |
| W8A8 | 64.000 | 9.012e14 | 4.00× |
| W4A4 uniform（无显著通道） | 16.000 | 2.253e14 | 16.00× |

**Ours 相对 Orig 的 ACE 差异 = +0.0000%。**
TinyLlama-1.1B 与 LLaMA-68M 结果一致（同为 15.61×，差异 0.0000%），JSON 已存 `log/`。

## 四、核心论点修正（请务必同步到论文叙事）

**此前（日志 012 及更早）我们默认"addbit 会带来约 +2.5% 的算力开销"，这个说法要改掉。**

理由：OSDSQ v2 与原版 SpikeLLM 使用**完全相同的位宽超参**（low_p、addbit、显著通道分配比例）。v2 的四项改动全部发生在**校准/训练阶段**：

| 改动 | 作用位置 | 是否改变推理位宽 |
|---|---|---|
| C1 均值锚定屏蔽（`_quant_low`） | 校准：min/max 求法 | **否**，只改 scale 数值 |
| 显著性度量（E + Δ_rel·Std） | 校准：mask_low 的选择方式 | **否**，比例仍是 10% |
| 蒸馏权重 w_main / w_cos | 训练损失 | **否** |
| GQA LET 修复 + real-multibit 零点补偿 | 校准 | **否** |

因此对外应表述为：

> **OSDSQ v2 在推理算力上与原版 SpikeLLM 严格等价（ACE 差异 0.0000%），同时把 LLaMA-7B W4A4 的 WikiText-2 PPL 从 10.5726 降到 7.9792（−24.5%）。**

这比"用 2.5% 算力换 24.5% PPL"干净得多，且是可验证的结构性结论，不是拟合出来的。

## 五、口径校验与风险

### 5.1 与原文 Table 5 的绝对量对比

| | 脚本 | 原文 | 差 |
|---|---|---|---|
| LLAMA-1-7B dense ACE | 3.605e15 | 3.886e15 | **−7.8%** |

差值可由统计细节解释（原文可能计入了 embed 层或采用不同 seqlen）。**所有对外结论均用比值表述，不受该常数因子影响。** 若审稿人追问绝对值，我们在附录注明 MACs 计数规则。

### 5.2 一个必须避开的坑：不能与原文 10.79× 横比

原文 Table 5：`SpikeLLM_T=2` 相对 dense 为 **10.79×**，反推其显著通道占比约 **52%**；而我们的配置是 low_p=0.9，即显著通道仅 **10%**，故为 **15.61×**。

**两者超参不同，不可直接横比。** 论文里必须写成"在相同 p 与 addbit 下与原版对比"，否则会被审稿人抓成不公平比较。

### 5.3 已知近似

- 注意力部分（QK^T / AV）无 weight，严格说应只按 activation 位宽计；本脚本对全部 MACs 统一乘 E[bit_w·bit_a]。影响量级：attention 仅占 3.9% MACs，误差 < 1%，可接受，但需在方法里说明一句。
- KV cache 的读写不计入 MACs，与原论文口径一致。
