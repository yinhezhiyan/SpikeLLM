## 2. 发现的问题
1. **我们“复现”的 Original 比原论文自己的 SpikeLLM 还好 1.4 个 PPL（10.57 vs 11.93）**。最可能的原因是我们两条腿都开了 `--aug_loss`（原文 7B 没开），另外还有 transformers 版本、lm-eval 版本差异。这不是坏事（说明我们的基线更强），但**我们现在无法声称“已复现原论文”**，审稿人拿原文表格一对就会问。
2. OSDSQ v2 的 Component D（双目标 + 余弦）本来就依赖 aug_loss，所以主表必须保留 aug_loss；同时需要补一行“原论文协议（无 aug_loss）”作为复现校验。
3. 原论文在 LLaMA-2-7B 上相对 OmniQuant 的零样本提升只有 +0.5，PPL 改善 22%。我们 7B 上相对 Original 的 PPL 改善 24.5%，量级相当，说服力主要来自“与原版同协议下的相对增益”，而不是绝对数。
4. 原论文已经和 QuaRot 做了对比（Table 4：SpikeLLM 叠加在 QuaRot-RTN/GPTQ 上，W4A4 LLaMA-2-7B 零样本 60.74 / 66.76），并用了 ACE / Sparse ACE 作为算力指标（Table 5）。**所以我们此前“缺 SNN 指标”的判断要具体化：必须提供同口径的 ACE / Sparse ACE。**
5. 原论文明确写了 LLaMA-2-70B 的 W4A4 / W2A8 **因为 GQA 训练不稳定而没有评测**。我们的 GQA-LET 修复（transformation.py）正好对应这个缺口，这是一个真实可写的贡献点（LLaMA-3-8B 同为 GQA，70B 为 GQA）。

## 3. 论文叙事建议（冲顶会的关键）
- 不再写“四个技巧堆叠”，而是：**原版 SpikeLLM 的低显著组校准被高显著通道污染 → 均值锚定屏蔽；显著性度量用步长加权；蒸馏目标加余弦；GQA 稳定化 + 零点 bug 修正**，并且用 ACE/Sparse ACE 证明不增加算力。
- “真实多步脉冲仿真”结果是我们的差异化点：原论文只在 GPU 多比特路径评测，我们验证了拆成 1-bit 脉冲后数值等价且无损（7B：real_multibit 与 fake_binary 降幅一致）。
- 更强的叙事：叠加在 QuaRot 之上也有效（原论文有此设置，我们在这个设置下也要复现并超过）。
