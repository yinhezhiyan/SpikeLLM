## 三、我的判断：三处采纳，一处纠正，一处不同意

### 3.1 采纳（已落到包里）

- **`env_report` 缺失 = 不可入账**。这是我自己的规程与实现不一致，Codex 抓得对。已把结果文件里的措辞改成"本轮结果按规程【不可入账】"。
  - 但我**没有**改成硬阻塞。理由：实验室只有一个人、一条网线，env_report 因无关紧要的原因报错就卡住整晚，代价不对称。宁可跑完、标记不可入账、次日补指纹。
- **表述统一**：包里每条腿的打印从 `addbit=3 (T=8)` 改为 `fake=高显著 7-bit / 真实脉冲 T=8`，并在头部加了一段澄清。避免回传时被误读成"我们测了时间步"。
- **Pareto 与 saliency-vs-random 进实验计划**：这两条我上一轮已列为待办，Codex 独立提出同一件事，说明这不是我的偏见。等第八轮出数后按结果决定先跑哪条。

### 3.2 纠正（Codex 有一处判断需要改）

Codex 说"`addbit=3` 同时改变位宽与 steps，不能当单因素对照"。**方向对，但结论要改**：
`spike_linear.py` 的 `forward()` 里，`self.steps` 只出现在 `fake_multibit_simulate` 与 `real_multibit_simulate` 两个分支；默认的 `fake_binary_simulate` 只走 `act_quantizer_high(inputs)`，而它的 `n_bits = 4 + addbit`（`quantizer.py:48`）。`main.py:412` 只在 `--sim_mode` 非默认时才切模式。
**所以本轮 fake PPL 是一次干净的高显著分支位宽对照，steps 完全没参与前向。** T=8 是同一笔预算在真实脉冲路径里的记法（2^addbit 个时间步 ≈ addbit 个额外比特），不是第二个变量。
这条我已写进脚本头部，避免实验室或后人再困惑一次。

### 3.3 不同意（这是本轮最重要的一条）

Codex 的药方 —— 造一个"按边际失真/成本分配预算"的新分配器 —— **方向正确，但在 11 周内做不出来**，而且做了也未必赢：
- 它需要逐个通道测"边际失真"，这本身是一套新方法（要设计、要调、要证），不是一次实验；
- 它和 SpikeLLM 自己的 saliency 分配区分度不够清楚，审稿人会问"你和 Optimal Brain Spiking 的差别是不是只是换了个重要性指标"；
- 它要求真实发放率与物理成本闭合，而我们连 Sparse ACE 的发放率都没测。

**但 Codex 自己写的一句总结，比它的方案值钱**：
> "Saliency-guided spiking quantization should allocate both coding budget and calibration domain to the same subset."

这句话把我们的"量程隔离"从"一个实现缝隙"提升成"**分配与统计域的一致性**"：显著性决定了谁多拿预算，但没人检查"算 scale 时用的集合"是不是同一批通道。两者不一致，分配就漏了。这个提法有三个好处：
1. 它是**可证伪的命题**，不是技巧描述；
2. 它天然解释了为什么 24% 这么大——因为漏的不是参数，是分配的语义；
3. 它给 addbit 扫描一个正当位置：加预算（addbit）与改统计域（我们）是**同一枚硬币的两面**，前者买精度要花钱，后者不花钱。

所以我的结论：**采纳 Codex 的"一致性"提法作为论文主线，拒绝它的"新分配器"作为本期工作**。论文主线从"我们提出均值锚定/量程隔离"改成：

> 显著度路由只分配了编码预算，却没有把量化统计域分配给同一子集；这个不一致是免费的，修好它拿回 24%。

这条不需要新算法，只需要把已有的四块证据摆齐：24%（已有三种子）、零开销（ACE 相等）、Pareto（第八轮）、选对子集（随机屏蔽对照，已有 68M 的弱证据，需按完整配置重跑）。
