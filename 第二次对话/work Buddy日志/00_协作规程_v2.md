## 0. 用户 2026-11-04 定下的硬规则（原文见 workbuddy日志_002）

1. **除各自日志文件夹与记忆文件夹外，不得新建任何文件。** 读取不设限。
2. **实验室命令由 WorkBuddy 单独对接与打包**，其他两方不直接给实验室下指令。
3. **Codex 只提建议、只分析实验室日志，不得修改项目代码。**
4. **WorkBuddy 也不得擅自修改项目代码。**
5. **修改项目代码的任务只属于 Antigravity。**
6. **每次工作前，先读另外两方的最新日志。**

## 2. 分工

- **WorkBuddy（我）**：论文主笔、实验设计、数据核验、**实验室唯一接口**（出包、收包、判读）。
- **Antigravity**：唯一的代码作者。改 `SpikeLLM/`、写 runner 的执行逻辑、修 bug。
- **Codex**：独立复核。分析实验室日志、审计数字、读外部仓库给结论、对论文提反驳意见。**不动代码，不出包。**

三方不重叠，是为了让"不同意"这件事有人负责：如果三个人都在写代码，就没有人认真怀疑代码。

## 3. 日志格式（五节，缺一不可）

用户原话 / 我做了什么 / 结论 / 待他人行动 / 风险。
判断与事实分开写；数字必须能追到文件路径，追不到标【无出处】。

## 4. 实验包的规矩

- 包内只有一个自定位 `.ps1`（头部注释即文档），用 Python `zipfile` 打，**条目名用正斜杠**。
- runner 固定 `$ErrorActionPreference = "Continue"`（`Stop` 会被 python 的 stderr warning 杀掉子进程）。
- 每轮包必须带 `env_report.py` 指纹，否则结果不入账。
- 包放在 `第二次对话/实验室命令/`，命名 `lab_roundN_<主题>_<日期>.zip`。

## 5. 冲突处理

数字对不上时，以能追到原始日志的一方为准；都对不上就补一条实验，不做口头裁决。
三人意见不一致时，把分歧写进各自日志，由用户拍板。
